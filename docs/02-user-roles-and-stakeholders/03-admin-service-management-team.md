# Admin / Service Management Team

## Role Name

**Admin / Service Management Team**

## Arabic Name

**الأدمن / فريق إدارة الخدمات**

---

## Role Status

**Included in Version 1**

---

## Role Description

The Admin / Service Management Team is responsible for managing paid booking requests after they are submitted by customers.

In Version 1, the customer can book and pay only if the selected service and date/time are available in the system. After payment, the request is sent to the admin panel.

The admin does not normally accept or reject the request after payment. Instead, the admin reviews and manages the paid booking request, assigns the suitable technician or employee, follows up on the service process, and updates the request status until completion.

---

## Main Purpose

The main purpose of this role is to organize service operations and make sure that paid customer requests are handled correctly from booking until service completion.

---

## Access Point

The Admin accesses the system through:

* Admin Panel / Management Dashboard

---

## Version 1 Booking Scenario

The booking process in Version 1 follows this flow:

1. The customer chooses the required service.
2. The customer chooses an available date and time.
3. The customer enters the property information.
4. The customer confirms the booking details.
5. The customer pays for the service.
6. The paid request goes to the admin panel.
7. The admin reviews the request details.
8. The admin assigns the suitable technician or employee.

---

## Admin Permissions

The Admin / Service Management Team can:

* Log in to the admin panel.
* View paid booking requests.
* View booking details.
* View customer information.
* View property information entered during booking.
* View selected service type.
* View whether the request is normal or emergency.
* View the customer problem description.
* View booking date and time.
* View payment status.
* Review and manage paid booking requests.
* Review request details and assign the suitable technician or employee.
* Update request status based on the service progress.
* Track active requests.
* Track completed requests.
* Track cancelled requests.
* Contact the customer if more information is needed.
* Manage available services.
* Manage service categories.
* Manage available booking times.
* View customer ratings after service completion.
* Handle customer support requests.
* Manage emergency requests with higher priority.

---

## Admin Request Management Flow

1. The admin logs in to the admin panel.
2. The admin views new paid booking requests.
3. The admin reviews the request details.
4. The admin checks the service type, property information, date, time, and payment status.
5. The admin assigns the suitable technician or employee.
6. The admin updates the request status based on the service progress.
7. The admin contacts the customer if there is missing or unclear information.
8. The admin follows up until the service is completed.
9. The admin closes the request after completion.

---

## Request Statuses

The admin can update or monitor request statuses such as:

* Paid
* Assigned to Technician
* In Progress
* Completed
* Cancelled

---

## Emergency Requests

Emergency requests should appear clearly in the admin panel with higher priority.

The admin should be able to quickly identify emergency bookings, review the problem description, and assign the suitable technician or employee as soon as possible.

---

## Important Version 1 Rule

In Version 1, the admin does not normally accept or reject a request after payment.

The correct admin responsibility is:

**Review and manage paid booking request.**

Or:

**Review request details and assign technician.**

This means that the customer pays only after selecting an available service and available date/time from the system.

---

## Cancellation Note

Cancellation after payment should happen only in exceptional cases, such as:

* The service cannot be provided.
* The address is outside the service area.
* The booking information is incorrect.
* The selected service does not match the actual problem.
* The request requires a different price or special inspection.

If cancellation happens after payment, the system should later support a clear cancellation and refund process.
