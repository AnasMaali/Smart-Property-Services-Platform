# Technician / Service Employee

## Role Name

**Technician / Service Employee**

## Arabic Name

**الفني / موظف تنفيذ الخدمة**

---

## Role Status

**Version 1: Included as an assigned service employee, managed by Admin**

**Version 2: Can have a separate account and dashboard**

---

## Role Description

The Technician / Service Employee is the person responsible for performing the service assigned by the Admin / Service Management Team.

This role may represent different types of service workers, such as electricians, plumbers, cleaning workers, renovation workers, AC technicians, maintenance employees, or service teams.

In Version 1, the technician does not need a separate account inside the system. The admin assigns the technician to a service inside a paid booking request and manages the request status from the admin panel.

Because Version 1 supports cart-based booking, one booking request may contain one service or multiple services. Therefore, the technician may be assigned to a specific service item inside the booking, not necessarily to the whole booking.

In Version 2, the technician may have a separate account or dashboard to view assigned tasks, update progress, and communicate with the admin or customer when needed.

---

## Main Purpose

The main purpose of this role is to execute the service assigned by the admin and help complete the customer’s booking request properly.

---

## Version 1 Scope

In Version 1, the Technician / Service Employee is managed by the Admin / Service Management Team.

The technician is connected to the booking through the assigned service item.

The technician does not directly log in to the system in Version 1.

---

## Version 1 Responsibilities

In Version 1, the technician is responsible for:

* Receiving the assigned service task from the admin.
* Understanding the service details.
* Visiting the customer’s property at the scheduled date and time.
* Performing the assigned service.
* Informing the admin about the service progress.
* Informing the admin when the service is completed.
* Reporting any issue that prevents service completion.
* Providing notes to the admin if needed.

---

## Technician Assignment in Cart-Based Booking

In Version 1, one paid booking request may contain one or more services.

Example:

* AC Cleaning
* Sofa Cleaning
* Curtain Installation

The admin may assign:

* AC Cleaning to an AC Technician
* Sofa Cleaning to a Cleaning Team
* Curtain Installation to a Handyman

This means that different services inside the same booking may have different technicians or service employees.

---

## Version 1 Admin Control

In Version 1, the admin handles technician-related actions inside the system, such as:

* Assigning a technician to a service inside the booking.
* Assigning different technicians to different services if needed.
* Updating the general booking status.
* Updating service item status if needed.
* Marking the service as in progress.
* Marking the service as completed.
* Adding internal notes if needed.
* Following up with the customer when needed.

---

## Possible Service Item Statuses

Each service item inside a booking may have its own status if needed.

Possible service item statuses may include:

* Assigned
* In Progress
* Completed
* Cancelled

The overall booking status may depend on the status of all service items inside the booking.

---

## Version 2 Scope

In Version 2, the Technician / Service Employee can have a separate system account or dashboard.

This will allow the technician to manage assigned tasks directly through the system.

---

## Possible Version 2 Functions

The technician may be able to:

* Log in to the technician dashboard.
* View assigned service items.
* View customer contact details needed for the visit.
* View property information and location details.
* View service type and service details.
* View booking date and time.
* Start the assigned service task.
* Update the service item status.
* Add service notes.
* Upload photos before or after the service.
* Mark the service as completed.
* Report that the service could not be completed.
* Contact the admin for support.
* Receive notifications for new assigned tasks.

---

## Request Flow in Version 1

The Version 1 flow is:

1. The customer adds one or more regular services to the cart.
2. The customer enters property information.
3. The customer chooses one available date and time for the whole cart.
4. The customer confirms the cart and pays once.
5. The paid cart becomes one booking request.
6. The booking appears in the admin panel.
7. The admin reviews the booking and its services.
8. The admin assigns the suitable technician or employee to each service if needed.
9. The technician performs the assigned service.
10. The technician informs the admin about progress or completion.
11. The admin updates the request status.
12. The request is closed after all required services are completed.

---

## Request Flow in Version 2

The possible Version 2 flow is:

1. The paid booking request appears in the admin panel.
2. The admin assigns technicians to the required service items.
3. Each technician receives the assigned task.
4. The technician logs in to the technician dashboard.
5. The technician views the assigned service details.
6. The technician starts the service.
7. The technician updates the service item status.
8. The technician adds notes or photos if needed.
9. The technician marks the service as completed.
10. The admin reviews and closes the booking request when all services are completed.

---

## Notes

* In Version 1, the technician does not need a separate account.
* In Version 1, the admin manages technician assignment and request status updates.
* In Version 1, technicians can be assigned to specific services inside a booking.
* One booking may have one technician or multiple technicians depending on the selected services.
* In Version 2, the technician can have a dedicated dashboard.
* Technician accounts can be added later without changing the core booking idea.
* This role is important because it represents the actual service execution stage.
