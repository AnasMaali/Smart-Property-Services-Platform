# Notification Service

## Role Name

**Notification Service**

## Arabic Name

**خدمة الإشعارات**

---

## Role Type

**System Component / Non-Human Stakeholder**

---

## Role Status

**Future Component — Not Included in Version 1**

---

## Description

The Notification Service is a future system component that will be responsible for sending important updates to users during the service booking and management process.

It can help customers, admins, and later technicians stay informed about important actions such as payment updates, booking updates, technician assignment, request progress, service completion, and support messages.

In Version 1, this component will not be implemented as a full notification system. Users can track their request status directly from the platform.

---

## Main Purpose

The main purpose of the Notification Service is to improve communication between the system and users by keeping them updated about important events and service request changes.

This component can reduce the need for manual follow-up and improve the user experience in future versions.

---

## Possible Future Notification Channels

In future versions, notifications may be handled through:

* In-app notifications
* Email notifications
* SMS notifications
* Mobile push notifications

---

## Possible Future Notification Events

The system may send notifications for:

* Payment successful.
* Payment failed.
* Booking request submitted.
* Paid booking request received by admin.
* Technician assigned to the request.
* Request status changed.
* Service started.
* Service completed.
* Service cancelled.
* Emergency request submitted.
* Customer support message received.
* Subscription renewal reminder in future versions.

---

## Customer Notifications

In future versions, the Customer may receive notifications when:

* The payment is completed successfully.
* The payment fails.
* The booking is submitted successfully.
* A technician is assigned.
* The request status changes.
* The service is completed.
* The customer is asked to rate the service.

---

## Admin Notifications

In future versions, the Admin / Service Management Team may receive notifications when:

* A new paid booking request is received.
* An emergency request is submitted.
* A payment is completed.
* A customer support request is received.
* A booking needs follow-up.
* A request is cancelled.
* A service is completed.

---

## Technician Notifications

In Version 1, technicians do not have separate system accounts.

In future versions, when technician accounts or dashboards are added, the system may send notifications to technicians when:

* A new task is assigned.
* A task is updated.
* A customer adds new information.
* A task is cancelled.
* A service time is changed.

---

## Version 1 Decision

The Notification Service will not be implemented in Version 1.

In Version 1, users can follow request updates by checking the request status inside the website or mobile application.

This keeps the first version simpler and focused on the core booking, payment, admin management, and service tracking flow.

---

## Future Notes

In future versions, the Notification Service can be added to support:

* In-app notification center.
* Email notifications.
* SMS notifications.
* Mobile push notifications.
* Technician notifications.
* Scheduled reminders before service time.
* Subscription renewal reminders.
* Notification preferences for users.

---

## Notes

* The Notification Service is not a human user.
* It is a future system component.
* It is not included in Version 1.
* It can be added after the main booking and tracking system is completed.
* In Version 1, request updates will be available through the request status page only.
